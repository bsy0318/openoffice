# 한글 메모 지원 계획과 기록

상태: **구현됨**(2026-10-26). 엔진 패치 0018, 앱 패널·평문 편집기, 저장 손실 확인, AI 읽기·앵커 삭제 승인, 21개 언어 문구를 넣었다. 빌드한 앱에서 목록·고치기·넣기·지우기·실행 취소·HWP/HWPX 저장·다시 열기와 모달 잠금을 확인했다. 한컴 한글 2024가 이 PC에 없어 한컴에서의 표시·왕복은 확인하지 못했다. 상위 rhwp PR #8269를 냈고, CI 결과를 기다린다.

## 1. 목표

한컴 한글 2024가 문서에 담는 메모(본문·표 칸·글상자)를 이 앱에서 읽고, 목록으로 보여 주고, 새로 넣고, 평문으로 고치고, 지우고, 원래 형식으로 저장한다. 앱에서 고친 메모는 한컴에서 메모로 보여야 하고, 한컴에서 고친 메모는 앱에서 보여야 한다. AI는 메모를 읽을 수 있지만 앱이 시키지 않은 메모 쓰기는 하지 않는다.

## 2. 범위

- 읽기: 본문, 표 칸, 글상자. 여러 문단에 걸친 앵커와 같은 문단의 여러 메모.
- 쓰기: 한 영역에 새 메모 하나. 기존 메모의 본문 고치기·지우기. 새 메모의 작성자는 사용자 이름 설정 → PC 계정 이름 → `IeumOffice`(제품 이름).
- 읽기 전용: 서식이 섞인 메모, 지원하지 않는 자리(머리말·각주 등), 암호 문서. 읽기 전용이어도 보호 문서·주소 없는 자리가 아니면 지울 수 있다.
- 저장: `.hwp`는 HWP, `.hwpx`는 HWPX. 메모가 없는 문서의 저장 결과는 예전과 같다.
- 메모 편집기가 열린 동안 저장·닫기·종료를 막고, 입력한 글을 버리지 않는다.
- AI: 메모 읽기 도구만 둔다. AI의 편집이 앵커를 지우려 하면 그 요청에 한해 승인을 받는다.
- 이번에 하지 않는 것: 한컴처럼 여백에 메모 상자를 그리는 화면, 메모 인쇄·PDF 포함, 메모 서식 편집, 메모 검색 전용 화면, 앱 밖에서 메모 쓰기.

## 3. 엔진

`vendor/rhwp-core`의 rhwp 0.8.7에 `patches/0018-memo-support.patch`를 건다. 이 패치는 저장 바이트를 바꾸는 예외다(결정 0072).

- 메모를 `FieldType::Memo`(또는 `MEMO/` 명령)와 `Field::memo_paragraphs`로 모델에 둔다.
- HWP5는 제어 기록의 `%unk`, 여는 글자의 `%%me`, 구역 끝의 `MEMO_LIST`를 나눠 쓴다. HWPX는 `type="MEMO"`, `Author`·`Number` 파라미터와 메모 문단을 쓴다.
- API: `getMemoList`, `insertMemo`, `insertMemoByPath`, `setMemoText`, `removeMemo`.
- 주소: 본문은 구역·문단·문자 범위, 표 칸·글상자는 `controlIndex`·`cellIndex`·`paraIndex` 경로.
- HWP 저장은 메모 목록을 마지막 구역의 마지막 본문 문단 아래에 둔다(한컴 표본과 같다). 빈 문단을 더 쓰지 않아 저장을 되풀이해도 문단 수와 바이트가 같다. 읽을 때는 같은 구역에서 먼저 짝을 찾고, 구역마다 꼬리를 둔 예전 파일도 읽는다.
- 커서 자리(길이 0)의 메모는 그 자리에 친 글자로 늘어나지 않는다. 메모 본문의 `
`·`
`은 `
`으로 바꾸고 다른 제어 문자는 버린다. 메모 넣기 요청은 JSON 파서로 읽는다.
- 앵커 글자를 통째로 지우면 같은 실행 취소 단계에서 메모를 지운다. 키로 지운 경우 편집기의 실행 취소는 원래 글자만 되돌리므로, 앱의 studio 패치(`studio-memo-anchors`, `studio-memo-delete-undo`)가 지우기 전에 그 문단을 잡아 두어 메모째 되돌린다. 일부만 지우거나 바꾸면 메모를 남기고 범위를 조정한다. 메모가 아닌 필드는 건드리지 않는다.
- 다른 문서에서 붙인 메모 필드는 버리고 글자만 붙인다. 같은 문서의 복사·붙이기는 메모 번호와 끝 표식을 새로 매긴다.
- 한 메모의 본문은 100,000 UTF-16 단위, 작성자는 64 단위까지다.

## 4. 앱

- `MemoPanel.tsx`가 AI 창과 같은 오른쪽 dock의 `메모` 모드에 목록을 그린다. 문서 순서, 작성자·쪽·날짜(파일이 담고 있을 때만)·미리보기, 읽기 전용 이유를 보여 준다. 카드를 고르면 앵커로 이동하고 앵커를 표시한다.
- `메모 넣기` 또는 편집기의 `Insert > Memo`가 평문 모달을 연다. 저장하면 곧바로 문서에 반영하고, 별도 적용 단계를 두지 않는다. `Esc`는 취소, `Ctrl+Enter`는 저장이다.
- 모달이 열리면 그 탭의 편집기 입력을 잠그고, `BroadcastChannel`과 main의 `memoModalByWc`로 다른 한글 탭도 잠근다. 저장 요청은 `memoSaveBlocked`를 보여 주고 거절한다(자동 저장은 조용히 건너뛴다). 탭 닫기·앱 종료는 main이 `closeMemoMsg`로 `버리고 닫기 / 취소`를 묻는다. 렌더러가 죽거나 다시 로드되거나 탭이 닫히면 main이 잠금을 풀고, 잠금은 한글 화면이 보낸 것만 받는다.
- 엔진 빌드에 메모 API가 없으면 `listMemos`가 `supported: false`를 돌려주고, 패널은 화면을 접은 뒤 `이 빌드에는 메모 기능이 없습니다.`를 한 번 알린다.
- 저장은 `save-flow.ts`가 편집기를 잠근 채 메모 목록을 읽고, 내보낸 바이트와 함께 `commitSave`로 넘긴다. `.hwpx`는 저장한 바이트를 다시 읽어 모델 메모와 원시 메모 기록 수를 견주고, 실제로 빠진 수가 있을 때만 `memoHwpxLost`를 보여 준다. 편집기 목록도 원본의 원시 기록도 0개면 엔진으로 다시 읽지 않는다. 저장 자체는 실패시키지 않는다.
- AI는 `listMemos`로 읽고, 앵커를 지우는 편집은 `allowMemoRemoval` 없이 `ask`로 거절한다. 사람이 승인하면 같은 호출을 보여 준 메모만 지울 수 있게(`approvedMemoIds`) 한 번 더 실행하고, 그사이 다른 메모까지 지워지게 되면 다시 거절한다. 승인 상태는 다음 요청으로 이어지지 않는다. 메모 패널의 편집은 사람의 편집으로 세어 AI 되돌리기가 건드리지 않는다.
- `packages/file-parse`의 `hwpToText`는 메모가 있으면 `### Comments` 블록을 붙이고, `hwpMemosOf`는 저장 검증용 구조를 돌려준다.

## 5. 문구

앱 바깥 문구는 `apps/hwp/src/renderer/i18n/app/<언어>.ts` 21개에 있다. `memoSaveBlocked`, `memoHwpxLost`, 읽기 전용 이유, 겹침·다중 문단·지원하지 않는 자리·보호 문서 거절, 복사 안내를 포함한다. 편집기 안 `Insert > Memo`는 한국어·영어 두 이름만 쓴다.

## 6. 시험

- 엔진: `apps/hwp/tests/engine-memos.test.ts` — 한컴 HWP 표본 읽기, 본문·표 칸·글상자 넣기/고치기/지우기, HWP·HWPX 왕복, `%%me`·`MEMO_LIST`·`type="MEMO"`, 앵커 전체/부분 삭제, 빈 대체, 복사, 보호 문서·겹침·범위 오류.
- 플러그인: `agent-plugin-memo-guard.test.ts` — 앵커 삭제 승인, 복사 경계, 서식 메모 읽기 전용, 거절 뒤 되돌리기.
- 패널·저장: `memo-panel.test.ts`, `memos.test.ts`, `tab-widths.test.ts`, `save-flow.test.ts` — 목록·모달·잠금, HWPX 손실 계산, 실제 엔진의 원시 메모 수, 저장 잠금과 경고.
- 빌드 앱: `e2e/hwp-memos.spec.ts` — 세 메모 목록, 본문 고치기, 새 메모 넣기, 모달이 열린 동안 저장·탭 닫기 거절, 지우기와 실행 취소, HWP 저장·다시 열기, HWPX 다른 이름으로 저장·다시 열기.
- 견본: `memo-source.hwp`는 한컴이 만든 HWP 표본이다. `memo.hwp`·`memo.hwpx`는 `apps/hwp/scripts/make-memo-fixtures.mjs`가 엔진으로 만든 작은 견본(본문·표 칸·글상자, 작성자 셋)이다. 한컴이 만든 HWPX 표본은 이 PC에 없어 넣지 못했다.

## 7. 확인하지 못한 것

- 한컴 한글 2024에서 새 메모가 메모로 보이는지, 한컴에서 고친 메모가 앱에서 보이는지. 이 PC에 한컴이 없다.
- 한컴이 만든 HWPX 메모 문서 읽기. 엔진이 만든 HWPX 왕복만 확인했다.
- 화면 나누기의 다른 쪽에서 모달이 열린 동안의 손 조작. 잠금 로직은 단위 시험으로 확인했다.
- HWPX 저장 손실 경고를 실제로 띄우는 화면 시험. 손실 계산은 단위 시험으로 확인했다.
- 상위 rhwp PR의 병합. [edwardkim/rhwp#8269](https://github.com/edwardkim/rhwp/pull/8269)를 냈고, 이 저장소의 기능은 그 결과와 무관하게 유지한다. CI 결과는 PR에서 확인한다.
